
## Запуск

```sh
go run .
```

Список URL и число воркеров (по умолчанию 5) заданы в `main.go`.
Отчёт содержит ID, URL, статус и фактическое время каждого запроса,
число заданий и успешных операций, среднюю и суммарную длительность
запросов, а также общее время работы пула. Суммарная длительность
запросов может превышать время работы пула из-за параллельного выполнения.

## Синхронизация

1. Отдельная горутина отправляет `Job` в `jobs`, затем закрывает канал.
2. Пять воркеров читают общий `jobs` — Fan-out и ограниченный Worker Pool.
3. Каждый воркер отправляет `Result` в общий `results` — Fan-in.
4. Отдельная горутина вызывает `wg.Wait()`, затем закрывает `results`.
5. Главная горутина читает результаты до закрытия канала, сортирует по ID
   и выводит отчёт. Только она изменяет слайс результатов и статистику.

Буферы обоих каналов равны числу воркеров: они не растут с количеством URL.
Отправка заданий и сбор результатов идут одновременно, поэтому заполнение
буферов не приводит к взаимной блокировке. Память для итогового отчёта
растёт линейно с количеством заданий. Пустой список корректно обрабатывается;
одинаковые URL сохраняются как отдельные задания с разными ID.

## Проверки

```sh
go test -timeout 30s ./...
go vet ./...
go test -race -timeout 30s ./...
```

Тест проверяет отсутствие потерь и повторов заданий, сохранение URL,
статус и длительность для пустого списка, одного задания и списка,
превышающего размер пула. В тесте используются небуферизированные каналы.
